# THG Sublime for Trilium — Phases 1 and 2

Phase 1 is live and accepted per the CLDS-0045 intake. It provides Sublime-inspired typography, desktop density, nine schemes and a bottom theme/status widget using Trilium v0.104.1 supported customization. **Phase 2 is implemented locally; its production deployment and human acceptance remain pending. Phases 3–5 remain open.** Scheme names describe original, variable-driven approximations; this package does not redistribute upstream theme packages or fonts.

Run local verification with Python 3.9+, Node 18+ and Chromium (no npm packages):

```sh
scripts/verify.sh
scripts/thg-sublime.sh apply --fixture
```

Verification needs Node 18+ to execute the JavaScript tests. `NODE_BIN=/path/to/node scripts/verify.sh` selects a standalone runtime; an invalid explicit override fails without silently substituting another runtime. Otherwise the resolver checks `node`, then `nodejs` on PATH. If neither is usable, it downloads the official Node **22.16.0** archive for Linux/macOS ARM64/x64 over HTTPS into the ignored workspace-local `.verify-runtime/` directory. The archive SHA-256 must match the platform digest pinned in `scripts/sublime/runtime.py` before any executable is written or run. Only the regular `bin/node` member is copied; npm and other archive paths are not extracted. No system installation or shell configuration changes occur. This pinned runtime is only for local verification, not the deployed product.

For offline/restricted-network hosts, either set `NODE_BIN` or preseed `.verify-runtime/node-v22.16.0-PLATFORM-ARCH.tar.xz` with the matching official archive from `https://nodejs.org/dist/v22.16.0/` (for example, `linux-arm64`). The resolver checks the archive on every run and reconstructs the executable from verified bytes. Removing `.verify-runtime/` removes the disposable runtime; a future run needs network or an explicitly supplied runtime again. Binaries are ignored and must not be included in the review/commit artifact. A missing or incompatible runtime is an error, never a skipped JavaScript suite.

The real-browser editor regression requires installed Google Chrome/Chromium 112+ on Linux or macOS. Discovery checks PATH, then standard macOS system/user Applications bundles (Google Chrome, Chromium and Chrome for Testing), or the existing Linux workspace browser. `CHROMIUM_BIN` overrides discovery and must name the executable, not the `.app` directory; invalid overrides fail explicitly. For example:

```sh
CHROMIUM_BIN="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" scripts/verify.sh
```

The runner uses [unified Chrome headless mode](https://developer.chrome.com/docs/automation-and-testing/headless) (`--headless=new`, including older supported Chromium). The offline fixture reports its computed-style result to a temporary server bound only to `127.0.0.1` on an ephemeral port. There is no ETAPI connection, browser download, npm dependency or remote debugging port. An explicit result replaces `--dump-dom` and waiting for Chrome shutdown, which timed out in the previous Mac preflight. Completion has a 45-second deadline; missing results, early exit and incorrect viewport sizes fail. The runner terminates/reaps its own process group and removes the temporary profile/log on success or failure. It never opens the operator's normal browser profile. Linux uses `--no-sandbox` for this disposable offline fixture; macOS keeps Chrome's sandbox.

On this ARM64 workspace Chromium is at `/usr/local/chromium/bin/chrome`; its missing Debian libraries were previously extracted into the ignored `.verify-runtime/browser-libs/` cache, without system installation. Only Linux uses that cache. Restricted execution environments need permission for browser processes and the temporary loopback server. Browser tests fail rather than skip when unavailable. macOS discovery and process handling have automated regression coverage; an actual Mac Chrome run remains an operator preflight requirement, not an asserted result from this Linux workspace.

Tests execute the packaged controller in a minimal DOM/widget contract harness and reconcile an in-memory ETAPI fixture, including second apply, disable/re-enable, partial update recovery and ownership conflicts. They check palette contrast (4.5:1 body/muted/accent text), module/breakpoint structure, baseline assets and Python/shell/JS syntax. The browser suite checks computed styles of real highlighted spans, native and drawn selections, active lines, gutters and carets for independently selected fixture light/dark editor palettes under all nine THG schemes plus invalid-value fallback, focused/unfocused and desktop/narrow layouts. It also proves the old partial recoloring fails. These are representative CM6 DOM/palette fixtures, not a running Trilium/CodeMirror instance. They do not emulate the whole Trilium browser or prove painted pixels, typing feel, live ETAPI interoperability or <200ms visible switching.

## Supported extension design

The source was inspected at the immutable [Trilium v0.104.1 tag](https://github.com/TriliumNext/Trilium/tree/v0.104.1). Relevant implementation contracts:

- [`desktop_layout.tsx`](https://github.com/TriliumNext/Trilium/blob/v0.104.1/apps/client/src/layouts/desktop_layout.tsx): `center-pane` is a vertical container whose custom widgets follow the split-note container. The status bar participates in flex layout, not a fixed overlay. Native split controls remain reachable.
- [`note_context_aware_widget.ts`](https://github.com/TriliumNext/Trilium/blob/v0.104.1/apps/client/src/widgets/note_context_aware_widget.ts), [`basic_widget.ts`](https://github.com/TriliumNext/Trilium/blob/v0.104.1/apps/client/src/widgets/basic_widget.ts), [`bundle.ts`](https://github.com/TriliumNext/Trilium/blob/v0.104.1/apps/client/src/services/bundle.ts): `api.NoteContextAwareWidget`, `doRender`, `refreshWithNote`, `cleanup`, `parentWidget`, `position`, `contentSized()` and an exported instance. Events update the active type without DOM polling or editor monkey-patching.
- [`bootstrap_utils.ts`](https://github.com/TriliumNext/Trilium/blob/v0.104.1/packages/trilium-core/src/services/bootstrap_utils.ts): `#appCss` supplies application CSS on frontend load. Eight `code` / `text/css` notes hold seven source modules and generated palette definitions. One `code` / `application/javascript;env=frontend` note with `#widget` holds the bundled controller. Labels are owned and non-inheritable. Phase 1 needs no backend script, custom endpoint or core patch. Phase 2 also keeps backend scripting disabled; explicit lock changes use the reviewed native frontend attribute routes described below.
- [`tab_row.ts`](https://github.com/TriliumNext/Trilium/blob/v0.104.1/apps/client/src/widgets/tab_row.ts) and [`tree.css`](https://github.com/TriliumNext/Trilium/blob/v0.104.1/apps/client/src/stylesheets/tree.css): selectors use `.note-tab[active]`, `.note-tab-wrapper`, `.fancytree-node` and `.ui-fancytree`. Native tab width/position calculations and drag handles remain in control. Tree hierarchy still has visible indentation.
- [`notes.ts`](https://github.com/TriliumNext/Trilium/blob/v0.104.1/apps/server/src/etapi/notes.ts), [`attributes.ts`](https://github.com/TriliumNext/Trilium/blob/v0.104.1/apps/server/src/etapi/attributes.ts), [`mappers.ts`](https://github.com/TriliumNext/Trilium/blob/v0.104.1/apps/server/src/etapi/mappers.ts): create-note supports caller-specified note IDs; attributes require IDs; content uses PUT; note reads include owned/inherited attributes and parent IDs. The global attribute GET is checked as well as note markers because attribute creation can upsert an existing ID. Deleted activation IDs can be recreated through the same supported endpoint.

Source modules live in `sublime/styles/`; `sublime/themes.json` separates `ui`, `editor` and reserved `syntax` tokens. `scripts/sublime/package.py` validates and deterministically packages them, retaining separate CSS notes. The status controller is in `sublime/controller.js`. No generated bundle needs to be checked into Git. No theme note with `#appTheme` is needed: the app CSS/controller pair owns the nine-scheme switcher, avoiding changes to Trilium's native theme setting or note language.

Default is **THG Sublime**. Other options: Materialize, Spacegray, Soda Dark, Soda Light, Guna, Mariana, Cyberpunk Umbra and Cyberpunk Scarlet. Neon colors are accents, with neutral body text. Phase 1 preserves the complete native CodeMirror palette, including its background, explicitly colored syntax spans, selections, active lines, gutters and caret. The THG switcher changes surrounding UI and rich-text surface colors, but a native dark code editor stays dark under Soda Light, and a native light editor stays light under dark THG schemes. Choose the code editor palette through Trilium’s native editor-theme setting. CodeMirror receives THG typography only; editor tokens color the rich-text surface and syntax tokens remain reserved for Phase 4. This avoids mixing incompatible native syntax colors with a replaced background. No full syntax mapping is claimed.

Typography uses `"Fira Code", "SFMono-Regular", Menlo, Monaco, Consolas, monospace`, 23px editor text, 30px line height and ligatures. Font availability is local to the client; none is bundled or fetched. Existing authored rich-text font choices and specialized/isolated editors may override typography. UI text is smaller for density. Tree rows become 26px; tab faces 30px within Trilium's native row geometry. Header spacing/title size are reduced without hiding actions, ribbons, promoted attributes or metadata. Search, attachments, protected notes, history, note operations, import/export and sync are not replaced.

The bottom bar shows the current note `type`, `UTF-8 · LF · Spaces: 4` and scheme picker. Encoding, line endings and indentation are **informational defaults**, not claims about the underlying note or overrides of native editor settings (also disclosed in the bar tooltip). Line/column is omitted because no cross-editor, split-safe public cursor API was verified. Phase 2 adds language evidence, lock state and a native language selector, described below.

Theme switching updates one root attribute synchronously, without rebuild or restart. Choice uses only `localStorage["thg.sublime.phase1.theme.v1"]`: global across notes, same-origin tabs and reload/reopen **within this browser profile**. It is not synchronized across devices/profiles, origins or user accounts sharing an origin. Storage events update other open tabs. Clearing/denying storage returns to THG Sublime on reload; blocked storage still allows session switching. Bad IDs fall back to THG Sublime; missing/malformed palette source fails packaging. The CSS base rule supplies default values for unknown DOM attributes. Theme changes install no timers. Language refresh uses the bounded debounce described below.

Density rules require `body.desktop` and width ≥901px. The bar hides at ≤900px, on `body.mobile`, and in print. Native mobile layout decides tabs/sidebar; no fixed widths or positioning are introduced. Schemes and editor typography may still apply on narrow desktop windows. If widget execution fails before render, scoped UI/editor CSS stays inactive and Lore retains its native layout. A partial CSS failure retains native controls. Initial install/update/disable needs Ctrl+Shift+R in each client; normal scheme changes do not.

## Phase 2 language intelligence

`sublime/language.js` is bundled into the existing widget note. All ten stable note IDs, the Phase-1 ownership namespace, nine schemes, theme storage key and activation labels remain unchanged. Updating the existing controller/status content uses the same fail-closed, dry-run-capable ETAPI reconciliation. No new note tree or endpoint is introduced.

Detection reads **unprotected, non-package code notes only**, through `FNote.getContent()`. Notes with any owned `thgSublimeOwner` marker (including empty or foreign values), rich-text, protected and other note types are not scanned; the selector is disabled. The desktop status includes note type, language, heuristic confidence and `Unlocked` or `Locked`, informational UTF-8/LF/Spaces fields and the original theme picker. Select a language (including Plain Text / Unknown) to lock, or **Auto (clear lock)** to return to detection. Manual results omit confidence. Unknown automatic results show 0%. Unsupported notes display Unknown. At ≤900px and on mobile the entire bar retains Phase 1's hidden fallback; use desktop for these controls. Desktop fields wrap to avoid overflow.

Scores are deterministic evidence strengths, **not statistical probabilities or accuracy estimates**. Each language requires at least two distinct rule families, scores 80 for two, 90 for three and at most 96 for four; a candidate must lead the runner-up by at least 10. A complete parseable JSON object/array with at least two entries scores 98. Fewer than 16 characters, a tie, insufficient grammar, or non-JSON lines longer than 1024 characters return Unknown. Complete JSON is parsed only up to 32,768 characters; other analysis samples only that prefix. SQL line comments, HTML comments, C-style block comments and full-line JavaScript/hash comments do not supply grammar evidence; shebangs, includes and Markdown headings retain their relevant roles. An explicit script shebang makes hash-prefixed headings and links comments, so they cannot supply Markdown evidence. Shell control words must occur as standalone commands, not words inside an echo/printf prose argument. File titles never override weak content evidence. This deliberately misses some valid one-line, minified and small programs. Rules are not full parsers: mixed languages, strings containing grammar and prose formatted like YAML/Markdown can still mislead them. No confidence score justifies a content or MIME write.

Auto state keeps an incumbent until a different candidate is observed in **two distinct changed samples** and exceeds the incumbent's evidence on the new content by at least 15. Unknown results (including tiny, empty, comments-only and ambiguous samples) immediately reset to Unknown at 0%, including unchanged refreshes, because current evidence cannot support a language. Manual locks still win over these samples. Returning to the incumbent resets the pending candidate; rereading identical content cannot manufacture evidence. `held` indicates pending change. Consequently a single complete paste may remain held until another content change; clear-lock/Auto explicitly resets this history. History is session-only, bounded to 64 notes and roughly 2 MiB of text; durable manual locks are separate. Content reload events are debounced 650 ms, not per-keystroke scans. Navigation reads immediately; generation guards discard late reads, cleanup cancels the timer/listeners and clears history. Trilium's supported content accessor may fetch its own note blob on cache miss; there are no detector service calls, cloud calls, polling or custom content transport.

### Durable lock contract and supported boundaries

The non-secret, non-inheritable owned label `thgSublimeLanguage` stores a stable language ID. Only owned labels are read, so a parent's lock does not propagate. **Backend scripting remains disabled.** The previous implementation failed live acceptance because `api.runOnBackend` requires globally enabled backend scripting. The public frontend script API exposes reads/reload but no direct label setter. The replacement is a small, version-pinned adapter to the native frontend attribute HTTP routes used by Trilium's own attribute controls; it is not a new public script API method, ETAPI exposure, imported private module or core patch.

On an explicit selector change, public `api.reloadNotes` / `api.getNote` first obtain fresh metadata and recheck code type, protection and absence of any owned `thgSublimeOwner` marker. A native `PUT notes/:noteId/set-attribute` creates or updates only the named label with `type=label`, the stable language value and `isInheritable=false`. Existing duplicate or inheritable lock labels refuse replacement and require explicit clear first, since the pinned setter updates only one existing value and does not change inheritance. Clear deletes only IDs returned by `FNote.getOwnedLabels('thgSublimeLanguage')` through `DELETE notes/:noteId/attributes/:attributeId`; it never submits the whole attribute list. This retains unrelated and inherited attributes and existing Phase-2 locks. Successful requests are followed by a public cache reload; remote attribute events also refresh the active note.

The adapter resolves `window.glob.baseApiUrl` against the page base and permits only same-origin HTTP(S) native `/api/` paths, including reverse-proxy prefixes. It uses the existing session cookie and in-memory `window.glob.csrfToken` header, matching native transport authentication. No ETAPI token is created, requested, stored or sent. Fetch has same-origin mode/credentials, redirects refused, caching disabled and a 10-second request timeout. Missing context, authentication/CSRF rejection, unsupported schemes, timeout or network errors show **Language lock not confirmed — reload or clear and retry**. There is no automatic write retry, error-body logging, bootstrap credential refresh or optimistic success. A timeout can have committed server-side: reload reconciles the durable state. Electron's custom protocol is deliberately unsupported by this web adapter and fails visibly; Lore browser use is the target.

Each native request runs in Trilium's normal transaction, without the backend scripting gate. Replacement is one request, rather than delete-then-create. Clearing multiple malformed duplicate labels uses separate requests and can partially complete on failure; retrying clear after reload is safe. Concurrent clients have native request ordering, without cross-client compare-and-swap. Fresh metadata prevents stale-cache package/type/protection mistakes but is not an atomic condition on a concurrent metadata change between read and write. The native endpoint has no such conditional-write contract. No content/type/MIME changes are made even in that race. Invalid language IDs display the distinct disabled placeholder so Auto can be chosen directly.

Pinned implementation references: [frontend script API](https://github.com/TriliumNext/Trilium/blob/v0.104.1/apps/client/src/services/frontend_script_api.ts), [FNote content and owned labels](https://github.com/TriliumNext/Trilium/blob/v0.104.1/apps/client/src/entities/fnote.ts), [native attribute client](https://github.com/TriliumNext/Trilium/blob/v0.104.1/apps/client/src/services/attributes.ts), [native transport/bootstrap context](https://github.com/TriliumNext/Trilium/blob/v0.104.1/apps/client/src/services/server.ts), [registered attribute routes](https://github.com/TriliumNext/Trilium/blob/v0.104.1/packages/trilium-core/src/routes/index.ts), [attribute handler semantics](https://github.com/TriliumNext/Trilium/blob/v0.104.1/packages/trilium-core/src/routes/api/attributes.ts), [session/CSRF middleware and transaction wrapper](https://github.com/TriliumNext/Trilium/blob/v0.104.1/apps/server/src/routes/route_api.ts), [reload events](https://github.com/TriliumNext/Trilium/blob/v0.104.1/apps/client/src/services/load_results.ts), and [native MIME catalogue](https://github.com/TriliumNext/Trilium/blob/v0.104.1/packages/commons/src/lib/mime_type.ts).

The explicit ID/display/MIME catalogue is `THG_LANGUAGES`. It covers Python, JavaScript, TypeScript, JSON, Shell, C, C++, Java, Kotlin, Swift, Rust, Go, YAML, SQL, HTML, CSS, Markdown, Dockerfile and Plain Text / Unknown. MIME entries mirror the pinned native catalogue and exclude executable frontend/backend JavaScript MIME variants. **Neither automatic detection nor manual locks apply MIME/type conversion at all.** The only user-note mutation is the label, guarded to unprotected code notes. Native MIME and editor highlighting remain under Trilium's own controls, consistent with the Phase-4 boundary. No content setter, formatting, type setter, core patch or direct DB/data access is involved. Removing the lock reverses the entire metadata change.

### Phase 2 verification and rollback
