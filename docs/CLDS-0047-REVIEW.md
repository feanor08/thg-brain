## Behavior and failure review

Normal UI says `Language: Python · Auto · 90%`, `Language: Rust · Manual`, or `Language: Unknown · Auto`. The separate highlighting field names authoritative highlighting and any desired mismatch without raw MIME strings. Native selects retain keyboard focus and help describing Auto, Manual and unchanged code. The existing wrapping bar and ≤900px/mobile fallback remain; all nine themes, informational fields and theme persistence remain intact.

Automatic writes require nonzero current evidence, a supported non-plain result and no pending hysteresis. Reconciliation checks fresh type, protection, ownership, current mode, evidence and MIME before mutation. Already-converged notes remain read-only; Unknown never changes MIME. Manual Plain Text is explicit intent. Auto removes only owned override IDs, including malformed duplicates, before re-detecting. Malformed inherited/duplicate overrides cannot be silently replaced.

Override and MIME writes have separate durable confirmations. Errors reload actual metadata, display actual Auto/Manual language with an unconfirmed-highlighting message, and block automatic writes. Session markers survive same-tab reload; explicit selection authorizes another attempt. Reopening a manual mismatch does not repair it automatically. A disabled error placeholder allows the current language to be selected again. Generation checks before/after awaits prevent a late operation from writing or repainting a newly active note. Native reload emits `notesReloaded`, not `entitiesReloaded`. Relevant entity events received while reading/writing are coalesced into one guarded debounced follow-up after the operation; navigation/dispose discards stale follow-ups.

Review limits: the native endpoint has no compare-and-swap or server-side eligibility predicate. A separate client changing type/protection/ownership after the final fresh read but before the native request is an unavoidable TOCTOU window on this surface. The adapter fails closed on changes visible at preflight and stops follow-up writes after navigation, but does not claim atomic cross-client exclusion. No core patch is introduced. Uncertain operations cannot be remembered in an unrelated browser session; denied session storage reduces that guard to bundle lifetime. The detector remains heuristic and can misclassify grammar inside strings or structured prose. Human acceptance and independent review must assess these native boundaries before production approval.

## Review-cycle repair

The previous Auto failure came from treating froca's merged attribute cache as a durable deletion confirmation. Inspected pinned [froca.ts](https://github.com/TriliumNext/Trilium/blob/744646d07bff459d1db305b1c0a8ea0c99b9c27c/apps/client/src/services/froca.ts): `addResp` merges returned attributes, while `reloadNotes` emits `notesReloaded`. Deletions may reach the cache later via entity updates. Every authoritative read now also uses session-authenticated `GET /api/notes/:noteId/attributes`, registered in the pinned routes index and implemented by [attributes.ts](https://github.com/TriliumNext/Trilium/blob/744646d07bff459d1db305b1c0a8ea0c99b9c27c/packages/trilium-core/src/routes/api/attributes.ts) `getEffectiveNoteAttributes`. It returns effective attributes; THG filters by exact owning note ID and label type, without modifying the native cache. Both override confirmation and managed-package exclusion use these fresh rows. Read failures fail closed. New source fingerprints accompany the existing pinned contract.

The second failure discarded external events during operations. Busy entity events now retain the affected note ID and schedule one 650ms refresh when all reads/writes finish. Native reload notifications do not feed this entity queue. Tests cover delayed deletion delivery, external edits after a content snapshot in read/manual operations, preserved hysteresis, convergence without further writes, and no follow-up loop. Chromium also retains deleted cached labels during the Auto restoration flow.
